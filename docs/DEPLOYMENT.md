# นำไปใช้งานบนเซิร์ฟเวอร์

## สิ่งที่ต้องมี

- Linux server หรือแพลตฟอร์มที่รัน Node.js 24 และ Chromium ได้
- พื้นที่เก็บข้อมูลถาวรสำหรับ SQLite ไม่ใช่ filesystem ที่ถูกล้างทุก deployment
- HTTPS reverse proxy และโดเมน หากเปิดให้ใช้งานผ่านอินเทอร์เน็ต
- การสำรองฐานข้อมูลที่เข้าถึงได้เฉพาะผู้ดูแล

แอปนี้ใช้ Node process เดียวกับ SQLite เหมาะกับการเริ่มใช้งานกลุ่มเล็ก การสร้าง PDF ทำครั้งละหนึ่งงาน งานที่ชนกันจะได้รับข้อความให้ลองอีกครั้ง ไม่มีค่าใช้บริการคลาวด์ภายนอกที่สร้างให้อัตโนมัติ

## ติดตั้ง

1. คัดลอกซอร์สและ package-lock.json ไปยังเครื่องที่ใช้รัน
2. ติดตั้ง Node.js 24 และ Chromium จากแหล่งของระบบที่เชื่อถือได้ โดยไม่ปิดการตรวจ TLS/ลายเซ็นแพ็กเกจ
3. รัน `npm ci` และ `npm test`
4. ตั้ง `PORT`, `CHROMIUM_PATH`, `BADGE_DATA_DIR` และ `PUBLIC_ORIGIN` ตามตารางด้านล่าง
5. รัน `npm start` ผ่าน process manager ของเซิร์ฟเวอร์ ให้เริ่มใหม่หลัง reboot
6. ให้ reverse proxy ส่งคำขอไปยังพอร์ตแอป ตั้งขนาด request body อย่างน้อย 50 MB และ timeout สำหรับ PDF ตามงานจริง ควรจำกัดคำขอ API/PDF ที่ proxy ด้วย
7. เปิด HTTPS แล้วทดสอบสมัครบัญชี บันทึก/เปิดโปรเจกต์ และ PDF จากโดเมนจริงอีกครั้ง

อย่าเปิดให้ดาวน์โหลดโฟลเดอร์ `.data`, Git metadata หรือไฟล์ config ผ่าน reverse proxy แอปมี allowlist สำหรับไฟล์ที่ให้บริการอยู่แล้ว อย่าแทนที่ด้วยการเปิด static directory ทั้งโปรเจกต์

## การเก็บข้อมูลและบัญชี

- รหัสผ่านเก็บเป็น scrypt พร้อม salt ไม่เก็บข้อความรหัสผ่านเดิม
- Session token เก็บเฉพาะแฮชบนเซิร์ฟเวอร์ คุกกี้ HttpOnly, SameSite=Strict และ Secure เมื่อ PUBLIC_ORIGIN เป็น HTTPS
- บัญชีนี้ยังไม่มีอีเมลยืนยัน ลืมรหัสผ่าน หรือระบบผู้ดูแล จึงต้องวางนโยบายจัดการบัญชีก่อนเปิดบริการสาธารณะขนาดใหญ่
- การล้างข้อมูลเบราว์เซอร์ไม่ลบงานบนเซิร์ฟเวอร์ แต่จะลบ autosave/เทมเพลต/เลย์เอาต์ในเบราว์เซอร์
- มีเพดาน 50 โปรเจกต์ต่อบัญชีและ 50 MB ต่อคำขอ ต้องติดตามพื้นที่ดิสก์และจำกัดการสมัครบัญชีที่ reverse proxy ตามการใช้งานจริง

## สำรองและย้ายเครื่อง

ทางง่าย: หยุดแอปก่อนสำรอง แล้วคัดลอกทั้ง BADGE_DATA_DIR ไปยังพื้นที่ปลอดภัย จากนั้นเริ่มแอปใหม่ หากสำรองขณะทำงานให้ใช้วิธี SQLite backup ที่รองรับ WAL แทนการคัดลอกเฉพาะ studio.sqlite ระหว่างมีการเขียน

ทดสอบกู้คืนบนเครื่องแยก ตรวจเข้าสู่ระบบและเปิดรูปต้นฉบับก่อนถือว่าสำรองสำเร็จ เก็บ JSON ของโปรเจกต์สำคัญเป็นสำเนาเพิ่มเติม

## งานพิมพ์และเครื่องตัด

ความแม่นยำไฟล์ไม่รับประกันกลไกเครื่องพิมพ์ ต้องพิมพ์ทดสอบที่ 100% และวัดจริง เครื่องหมายจัดตำแหน่งเป็นกากบาททั่วไป ไม่มีการรับรอง Print Then Cut ของเครื่องรุ่นใดโดยยังไม่ได้ทดสอบซอฟต์แวร์และฮาร์ดแวร์นั้น

## ตัวแปรสภาพแวดล้อม

| ชื่อ             | ค่าเริ่มต้น / ตัวอย่าง            | ใช้ทำอะไร                                                         |
| ---------------- | --------------------------------- | ----------------------------------------------------------------- |
| `PORT`           | `5173`                            | พอร์ตของแอป                                                       |
| `CHROMIUM_PATH`  | `/usr/bin/chromium`               | ตำแหน่ง Chromium สำหรับ PDF และชุดทดสอบเบราว์เซอร์                |
| `BADGE_DATA_DIR` | `.data` ในโฟลเดอร์โปรเจกต์        | ที่เก็บ SQLite และข้อมูลเซิร์ฟเวอร์ ต้องอยู่บนพื้นที่ถาวร         |
| `PUBLIC_ORIGIN`  | เช่น `https://badges.example.com` | Origin ที่อนุญาตให้เขียนข้อมูล; ใช้ HTTPS เพื่อให้คุกกี้มี Secure |

หากไม่ตั้ง `PUBLIC_ORIGIN` เซิร์ฟเวอร์ใช้ origin จาก Host ของคำขอ เหมาะสำหรับพัฒนาบน localhost การใช้งานสาธารณะควรตั้งค่า origin ให้ตรงโดเมนจริง

ซอร์สและ HTML ที่ส่งมอบอยู่บน branch `main` ของ [repository](https://github.com/mazarusgt/My-Badge-Studio) การ push โค้ดไม่ใช่การ deploy เว็บ ดูหลักฐานการตรวจล่าสุดที่ [STATUS.md](STATUS.md)
